# Browser MCP benchmark — 2026-08-19

`haden-browser 0.1.0` was compared with [Microsoft Playwright MCP 0.0.78](https://github.com/microsoft/playwright-mcp) and [Google Chrome DevTools MCP 1.7.0](https://github.com/ChromeDevTools/chrome-devtools-mcp). Chrome DevTools was run in both its default full mode and the officially documented `--slim` mode.

Each configuration ran five times in a fresh isolated process. Values below are medians. All 20 runs completed the article, form, computed-style, and image scenarios.

## Primary result: lowest semantic-browser token footprint

Haden used **7,822 reference tokens** for the core browsing session. That is **32.7% fewer than Playwright MCP** and **32.5% fewer than Chrome DevTools MCP full mode**. Among the tested MCPs that returned semantic action refs and image-alt coverage, Haden used the fewest tokens.

| Token metric | Haden | Playwright | Chrome Slim† | Chrome Full |
| --- | ---: | ---: | ---: | ---: |
| Core session | **7,822** | 11,627 | 4,638 | 11,596 |
| Tool schema | **727** | 3,999 | 221 | 4,974 |
| Article workflow | **2,732** | 4,640 | 2,497 | 4,388 |
| Form workflow | **421** | 861 | 156 | 914 |
| Computed-style workflow | 3,942 | 2,127 | 1,764 | **1,320** |

Core-session tokens include one complete `tools/list` schema load plus the MCP call names, arguments, and `CallToolResult` payloads for the article, form, and computed-style workflows. Counts use `js-tiktoken` with `o200k_base` over compact JSON. Image pixels, user/system prompts, and model reasoning or prose are excluded. Actual billed tokens vary by MCP host and model.

† Chrome Slim is the absolute token minimum, but it uses a different control model: the AI must author arbitrary JavaScript, and the tested paths returned no semantic action refs or image alt text. It is a useful low-level efficiency ceiling, not a drop-in semantic-browser equivalent.

## Findings

- Haden's tool schema used 81.8% fewer tokens than Playwright and 85.4% fewer than Chrome Full.
- Its article workflow used 41.1% fewer tokens than Playwright and 37.7% fewer than Chrome Full.
- Haden's built-in visual response was more detailed and used more tokens than the competitors' fixed-script results. The smaller schema and article/form payloads still made its complete core session about one-third smaller than both full semantic alternatives.
- Haden delivered the first useful article result 61.5% sooner than Playwright and 66.7% sooner than Chrome Full in this launch configuration.
- Blocking heavy assets reduced article origin transfer by 82.4% relative to every competitor configuration.
- The form workflow was 51.4% faster than Playwright and 45.8% faster than Chrome Full. Haden's one-call visual mode matched Chrome Slim's median while retaining a purpose-built representation.

Playwright MCP 0.0.78 writes automatic post-action snapshots to artifact files. The benchmark explicitly called `browser_snapshot` when inline page content was required. Artifact bytes and filesystem-read latency were not counted, so the reported Playwright context cost is conservative.

## Scope and limitations

- Windows x64, Node 22.22.2, Playwright Chromium revision 1234, 1280×800, headless and isolated.
- Local deterministic pages; no internet variability, login, CAPTCHA, downloads, iframes, or long multi-page research task.
- Competitors used their pinned `npx` launch paths with a warm npm cache; Haden used its local built entry point. Startup represents the tested deployment commands, not engine-only initialization.
- `o200k_base` provides a reproducible text-token reference. Different models and MCP hosts may serialize or tokenize tool traffic differently.
- The visual workflows return different amounts of detail. Haden's response contains its built-in bounded visual representation; the competitors returned the benchmark's fixed computed-style script result.
- This evaluates basic AI browsing efficiency, not feature completeness. Chrome Full provides network, Lighthouse, console, emulation, and performance capabilities outside Haden's MVP scope.

Raw per-run measurements and environment metadata are in [`latest.json`](latest.json). Re-run with `npm run benchmark -- --runs=5`.
